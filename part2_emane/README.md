\# Part 2 - EMANE TDMA Integration



\## 1. Objective



Part 2 extends the Python-based TDMA Network Brain from Part 1

towards a physical network simulation using EMANE.



The objective is to pass the TDMA schedule generated by the Python

scheduler into an EMANE TDMA Radio Model so that packet transmission

can follow the planned time-slot assignments.



The VMN assignment specifies the use of EMANE's native TDMA Radio

Model, with 1 ms slots, frames, and frequencies.

\## 3. Input from Part 1



Part 1 generates two related representations:



1\. Node-to-Slot mapping

2\. Slot x Node binary schedule matrix



Example Node-to-Slot mapping:



Node\_01 -> Slot 8

Node\_02 -> Slot 5

Node\_03 -> Slot 4

...

Node\_16 -> Slot 8



The schedule matrix contains:



1 -> node is scheduled in that slot

0 -> node is not scheduled in that slot



This matrix is the main logical input to the Part 2 integration

bridge.



\---



\## 4. Schedule Adapter



A Python schedule adapter is proposed between the Part 1 scheduler

and EMANE.



Responsibilities of the adapter:



1\. Read the generated TDMA schedule.

2\. Preserve the node-to-slot assignments.

3\. Convert the schedule into an EMANE-compatible schedule event.

4\. Represent the slot/frame information required by the EMANE

&#x20;  TDMA Radio Model.

5\. Provide the generated event/configuration to the EMANE simulation.



Conceptual flow:



Part 1 Schedule

&#x20;     |

&#x20;     v

Schedule Adapter

&#x20;     |

&#x20;     v

EMANE Schedule Event

&#x20;     |

&#x20;     v

TDMA Radio Model





The assignment allows the integration bridge to use an XML or

ProtoBuf schedule event recognized by EMANE.



\---



\## 5. TDMA Timing Model



The EMANE configuration is planned around the timing model specified

in the assignment:



\- Slot duration: 1 ms

\- Multiple slots form a recurring TDMA frame

\- Frequency configuration is defined in the EMANE TDMA Radio Model

\- Node transmission opportunities are determined by the generated

&#x20; schedule



For the current Part 1 sample, the Python scheduler generated

9 unique slots.



Therefore, the logical schedule contains 9 slot positions that can

be mapped into the corresponding TDMA frame configuration.



\---



\## 6. Schedule Enforcement Concept



The intended behavior is:



If a node is assigned to the current TDMA slot:



&#x20;   transmission is permitted according to the schedule



If a node is not assigned to the current TDMA slot:



&#x20;   transmission is not scheduled for that node in that slot



The EMANE simulation can therefore be used to observe whether

packets follow the planned TDMA schedule.



The expected integration goal is that packet delivery follows the

schedule generated by Part 1.

\## 8. EMANE Integration Steps



The proposed implementation sequence is:



\### Step 1 - EMANE Environment



Install EMANE on a single Linux environment or use one consolidated

Docker container.



\### Step 2 - TDMA Radio Model



Configure EMANE's native TDMA Radio Model.



The configuration will define:



\- TDMA slot duration

\- Frame structure

\- Frequencies

\- Radio/node configuration



\### Step 3 - Schedule Conversion



Pass the Python-generated schedule to the integration bridge.



The bridge converts the schedule matrix into the XML or ProtoBuf

schedule event required by the EMANE environment.



\### Step 4 - Apply Schedule



Load the generated schedule into the EMANE TDMA Radio Model.



\### Step 5 - Packet Verification



Create traffic between virtual nodes and observe packet delivery.



The expected behavior is that packet transmission follows the

assigned TDMA slots.

\## 11. Limitations



The current Part 2 work describes the integration approach rather

than claiming a completed EMANE packet simulation.



The exact EMANE schedule-event format must match the installed

EMANE TDMA Radio Model and its supported configuration/event

interface.



Therefore, the integration layer should be validated against the

specific EMANE version and TDMA model available in the target

environment before claiming successful packet-level execution.
